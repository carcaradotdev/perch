# Quick start

This page sets up two modules:

- `my-routes` declares the routes. It applies the producer plugin.
- `app` assembles the app. It applies the aggregator plugin and creates the parser.

Do the [installation](installation.md) steps first.

## 1. Apply the producer plugin

In the module that declares your routes, apply Kotlin Multiplatform, the kotlinx.serialization
compiler plugin, KSP and `dev.carcara.perch`. The versions come from the root build file.

```kotlin title="my-routes/build.gradle.kts"
plugins {
    kotlin("multiplatform")
    kotlin("plugin.serialization")
    id("com.google.devtools.ksp")
    id("dev.carcara.perch")
}

kotlin {
    // The producer plugin needs at least two targets.
    jvm()
    iosSimulatorArm64()

    sourceSets {
        commonMain.dependencies {
            api("dev.carcara.perch:perch-core:0.1.0")
        }
    }
}

perch {
    outputPackage.set("com.example.routes")
}
```

!!! note "Two targets or more"

    The KSP processor runs on the `commonMain` compilation. Kotlin Multiplatform creates that
    compilation only when a module declares two or more targets. This rule applies to the producer
    module only. The aggregator module can have one target.

## 2. Declare routes

Annotate a class in `commonMain` with `@DeepLink`:

```kotlin title="my-routes/src/commonMain/kotlin/com/example/routes/Routes.kt"
package com.example.routes

import dev.carcara.perch.DeepLink

@DeepLink("/home")
data object HomeLink

@DeepLink("/payments/{id}")
data class PaymentLink(val id: String)
```

A route does not implement an interface from Perch. It does not need `@Serializable` either:
`@DeepLink` is `@MetaSerializable`, so the kotlinx.serialization compiler plugin generates the
serializer.

The KSP contract has one rule. **A class annotated `@DeepLink`, in the sources of a module that
applies `dev.carcara.perch`, is a registered route.** The processor does not scan other modules.

## 3. Apply the aggregator plugin

In the module that assembles your app, apply `dev.carcara.perch.aggregation` and depend on the
routes module from `commonMain`:

```kotlin title="app/build.gradle.kts"
plugins {
    kotlin("multiplatform")
    id("dev.carcara.perch.aggregation")
}

kotlin {
    jvm()
    iosSimulatorArm64()

    sourceSets {
        commonMain.dependencies {
            implementation("dev.carcara.perch:perch-core:0.1.0")
            implementation(project(":my-routes"))
        }
    }
}

perchAggregation {
    outputPackage.set("com.example.app")
}
```

The aggregator generates `perchParser()` into the `commonMain` source set of `app`. The function
registers every route that `app` can reach through its `commonMain` dependencies:

```kotlin title="build/generated/perch/commonMain/kotlin/com/example/app/PerchDeepLinkRegistration.kt"
package com.example.app

import dev.carcara.perch.DeepLinkLogger
import dev.carcara.perch.DeepLinkParser

/**
 * A parser with every deep-link route reachable from this module already registered.
 * @generated by the generateDeepLinkRegistration Gradle task
 */
public fun perchParser(
  schemes: Set<String>,
  hosts: Set<String> = emptySet(),
  logger: DeepLinkLogger = DeepLinkLogger.None,
): DeepLinkParser = DeepLinkParser(schemes, hosts, logger).apply {
  register<com.example.routes.HomeLink>()
  register<com.example.routes.PaymentLink>()
}
```

You do not run the task yourself. Gradle runs it before it compiles `commonMain`.

## 4. Create a parser and parse a URL

```kotlin
import com.example.app.perchParser
import dev.carcara.perch.DeepLinkParser

val parser: DeepLinkParser =
    perchParser(schemes = setOf("myapp", "https"), hosts = setOf("myapp.example"))

when (val route = parser.parse("myapp://payments/abc123")) {
    is PaymentLink -> println("Open payment ${route.id}")
    is HomeLink -> println("Open home")
    else -> println("Not a Perch route")
}
```

`parse` returns the route object, or `null` if no route matches. The return type is `Any?`, because
Perch does not know what your routes have in common. To get a typed result, give your routes a
supertype of your own. See [Give routes a supertype](../guides/routes.md#give-routes-a-supertype).

The `hosts` argument is necessary because `schemes` contains `https`. See
[Schemes and hosts](../guides/schemes-and-hosts.md).

## One module only

If all your routes and the code that parses URLs are in the same module, you do not need the
aggregator. The producer plugin also generates `perchModuleParser()` into the module's own
`commonMain`:

```kotlin
val parser = perchModuleParser(schemes = setOf("myapp"))
```

`perchModuleParser()` is `internal`. Other modules cannot call it.
